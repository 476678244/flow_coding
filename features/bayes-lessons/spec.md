# spec · bayes-lessons

合同：看得见的一条带出处的观察 → 跨过进程退出再启动 → 仍能按同一个问题调出这条还成立的观察

无可见面（无 DOM）。不建 `demo.html`。

## 目标

为 AI Agent 提供一种认知建立的、认识世界的方法与路径。让 AI Agent 在日常的开发和 工作中也建立贝叶斯思维。

贝叶斯思维在这条路径上是三步，不是多记一份笔记：

1. 认识世界时只把已经发生、并且能指到出处的事当作事实。观点、推论、概率留在当次对话里，算完不写回去。
2. 下次面对同一个问题，先把还成立的事实全部调出来，当作第一次看见它们，重新判断。不把上次的结论当成先验。
3. 新事实若让旧事实不再成立，记下新事实并点名旧的那条。判断仍在对话里做。

日志让这条路径跨过进程还在。技能把这三步嵌进日常开发和 工作，而不是另开一种研究模式。

一个仓库一旦打开 `/bayes-lessons`，工作目录就是该仓库根上的 `.bayes_lessons/`。这个技能的数据只写在这里，不写到别的目录。

```
<仓库>/.bayes_lessons/
  meta.json      # 打开时保证存在。schema 版本
  facts.jsonl    # 只追加的观察。还没有观察时可以不存在
```

`note` 和 `recall` 都会先保证目录和 `meta.json` 存在。拒绝写入时不创建、不改动 `facts.jsonl`。以后若要新的一类数据，在这个目录里加文件，不另起根目录。

## 行为

入口是目标仓库根目录上的一个命令，两个动词：`note`、`recall`。技能 `/bayes-lessons` 写明日常路径，并在日志还空的时候走一段初始 investigate。这段顺序只调用这两个动词。命令行不接受第三个动词，也不出现柜子名。

一个仓库启用 `/bayes-lessons`，要同时有：根上的 `Soul.md`、`Agents.md`、`Index.md` 都写明已启用，并要求工作过程中先 `recall`、带出处再 `note`、结论不写入日志；以及根上的 `.bayes_lessons/`。三个文件不会自己建目录。目录在该仓库根上第一次 `note` 或 `recall` 时出现。启用之后，代理在这个仓库里的每一轮工作都按这三份文件维护并利用日志。

初次建立样本库由 `/bayes-lessons-setup` 负责。样本库是 `facts.jsonl`，不是 `meta.json`。这份文件还不存在时，先走 setup，把初步 investigate 的事实 `note` 进去，再做别的工作。日常维护走 `/bayes-lessons`，不建立第一份 `facts.jsonl`。空的 `recall` 只表示目录打开了，禁止把它当成已经建立先验。样本库记的是这库要认识的事情，不是代理从哪份文件读起。建立认知按南添的贝叶斯思维：事实是已经存在并且正在起作用的事；先验是全部还成立的事实；新事实来了就把它们摊开重算，结论不入库。规则写在 `/bayes-lessons` 的「贝叶斯认知」。默认问题是：「这个仓库是什么？」身份记 `Soul.md`、`README`、Index 里仓库自己的那几句。文件分工、启用说明、第一次 recall 的运行记录不充当样本。不要为了凑一条运行留下的行去记 recall 日志。文件已经在、但没有一条回答这句时，建立还没完成，不删已有行。旧信念不 `note`。没有和介绍不一致的差异，就不另写一句模型总结的「这个项目是什么」。然后再 `recall`。判断不入库。这一步仍只用 `note` 和 `recall`。

日常路径，按这个顺序：

1. 动手处理一个问题之前，先 `recall` 这个问题。
2. 只根据调出来的事实，在对话里做这次判断。
3. 做的过程里若确认了一件带出处的事，`note` 下去。
4. 这件新事让某条旧事实不再成立，用同一条 `note` 带上 `--retracts`。
5. 这次得出的结论不写入日志。

`recall` 还是空的、而眼前的工作需要一个先验时，先走下面的初始 investigate，再回到这五步。

### 初始 investigate

日志是空的时候，模型会凭记忆写一句「这个仓库是什么」。凭记忆的那句不是事实。事实是仓库文件里已经写着的那一行，身份也一样，一条一句记进去。初始 investigate 的意义，是在记忆句被写成之前，把空库填成一批可单独撤回的事实。贝叶斯先验指的就是这批事实。把事实调出来之后才有的判断，不能倒过来再存成先验。

它是技能里的一段顺序，不是一条命令。把 `investigate` 交给命令行，按 `unknown-verb` 拒绝。也不产生 `investigate.md`、`先验.json`，或任何结论文档。

顺序：

1. 先写下要回答的问题。没有问题，不开文件。
2. 在对话里说出打开仓库之前已经相信的那一句。这句话不 `note`。它是摘不掉的镜片，说出来是为了防止后面只捡能证明它的行。
3. 再看仓库。出处是仓库里已经有的一行。技能不代跑命令。不要为了凑一条运行留下的行，把 recall 的输出落成文件再记进去。
4. 每一条事实单独 `note`，各自有 id，日后能被单独 `--retracts`。不揉成一段「对这个仓库的理解」。
5. 仓库自己写明它是什么的那一句要记进样本，哪怕介绍里已经有。不记的是模型总结出来的「这个项目是什么」。`Soul.md` 没写这库是什么时，日志可以继续是空的。空着这时是诚实的，不是调查没做完。
6. 记完再 `recall`。判断在对话里说完即弃。事实第二天变了，用新的 `note` 撤回旧 id，不保留一份「曾经的洞察」。

技能同时要求做事的人对照三道门槛，命令行不给它们打分，也不因此多设字段：

身份那一句不受这三道限制。身份之外的新事实才对照：

- 这条是不是眼前这个问题要的事
- 它是否打脸第 2 步那句旧信念
- 它是否改变下一步怎么做

三道都答不上，而人仍想留下一句总结，就停，不要为了完成调查制造先验。哪一道算「缺了就是游览」，命令行不裁决。

### note

追加一条观察。

必填：

- `--about` 问题，调用者的话，原样保存
- `--claim` 发生了什么，一句
- `--evidence` 仓库内已存在文件上的行：`相对路径:行` 或 `相对路径:起-止`

路径必须落在当前仓库内。含 `..`、绝对路径、指向不存在的文件，都拒绝。

可选：

- `--retracts <id>` 仍是 `note`。新观察成立，并宣布该 id 不再成立。被点名的 id 必须已经在日志里，且 `about` 相同。

成功：向 `<仓库>/.bayes_lessons/facts.jsonl` 追加一行，stdout 给出新 id。文件只追加，不改旧行。

拒绝时进程退出码为 2，日志字节不变，stdout 是失败 JSON：

| reason | 何时 |
| --- | --- |
| `no-evidence` | 没有证据，或证据不是仓库内已存在的行 |
| `inference` | claim 含这些字样：`因此` `这说明` `我认为` `应该` `概率` |
| `unknown-verb` | 不是 `note` 也不是 `recall` |
| `bad-retract` | `--retracts` 的 id 不存在，或 `about` 不一致 |
| `corrupt-log` | 日志里有一行不是 JSON |

`inference` 是词表门，用来挡住把推论写进去。它不理解句子。

### recall

`--about` 必填，与 `note` 时的字符串精确相等才命中。

折叠日志：一条 `note` 若被后来的 `--retracts` 点名，它不再出现。撤回那一行本身还在，因为它是新的观察。

不匹配时退出码 0，`observations` 为 `[]`。不编造一条「没有记录所以大概是这样」。

stdout 里没有结论字段，没有概率，没有柜子。

## 先验

实现前，仓库里没有这条命令，也没有 `.bayes_lessons/`。

命令现在在 `skills/bayes-lessons/scripts/bayes.py`。观察只写在被打开的那个仓库的 `.bayes_lessons/`，不写在技能目录里。换一个仓库再打开，就是另一份工作目录。

## 不做

- 柜子、标签、权重、百分比、贝叶斯事件这个类型
- 把本次推论写进 `readings/` 或写回日志
- 合并同形句子、证据哈希、过期检查
- 代跑 `--evidence` 里的命令。要记命令结果，先把输出落成仓库里的文件，再记那一行
- HTTP、页面、`demo.html`
- 修洞关账后自动记一笔
- 第三动词，包括名为 `investigate` 的命令。撤回是 `note` 的字段。初始 investigate 只存在于技能顺序里
- `investigate.md`、`先验.json`，以及把旧信念或调查结论写进 `.bayes_lessons/`

## API 响应

无 HTTP。合同在命令的 stdout。空数据与失败都是完整 JSON，不靠空输出暗示成功。

### 请求

- 方法 / 路径：`python skills/bayes-lessons/scripts/bayes.py note|recall`，工作目录是被观察的仓库
- 查询或体：见上文字段。无请求体

### 成功（摘录）

`note`：

```json
{"id":"f-7c2a","status":"stored"}
```

日志追加的那一行：

```json
{"op":"note","id":"f-7c2a","ts":"2026-11-09T20:50:00+08:00","about":"重启后登录还在吗","claim":"重启后 session 键不在","evidence":"src/store.ts:40-48"}
```

带撤回时多一个字段 `"retracts":"f-7c2a"`，`op` 仍是 `note`。

`recall`：

```json
{"about":"重启后登录还在吗","observations":[{"id":"f-91b0","claim":"新进程读不到 session 键","evidence":"src/store.ts:40-48"}]}
```

### 空数据

```json
{"about":"重启后登录还在吗","observations":[]}
```

退出码 0。

### 失败

```json
{"error":"rejected","reason":"no-evidence"}
```

退出码 2。`reason` 只取行为一节那张表里的值。
