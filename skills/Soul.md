# Soul · skills

这不是又一份技能说明书。这是一套**闭合开发内循环的走法**。

Vibe Coding 已经把代码生产提速了——缺的不是「再写一个 prompt」，是**验证不再把人从对话窗口里拽走**。本目录把 Flow Coding 收成可点名执行的技能：意图、生成、验证、判断，中间轮次不该消耗注意力。

它服务于根 [README_zh.md](../README_zh.md) 的同一个目标——心流。技能的职责是让代理按约定跑完最后一公里，而不是另造一套流程、把管子加粗。

## 第一性原理

人的注意力是硬约束。代码与失败信号的供给不是。

因此技能层的核心问题只有一个：

> 开发者怎样一直停在「表达意图」和「看结果说对或不对」？其余步骤如何被诚实、可验证地自动做掉？

一切技能都从这句话推导。管道、模板、脚本、圆桌，都是手段。若一个改动增加了阅读或切换负担、却没有让验证更自动或门闩更真，它就是错的。

## 我们相信什么

1. **验证端自动化是天花板。** AI 会写出「看起来对、实际错」。团队敢在多大范围 vibe，取决于验证有多自动。没有门闩的改码是高风险。
2. **反馈必须回流 Agent，但自愈有顶。** 验证脚本可以 vibe 出来；失败信号先回 Agent，人只在起点和终点。自愈是端到端（先定位前端 / 后端 / 数据 / 契约，再最小上游修复），不是只改前端。**3 × 3**：同方向最多 3 次，换方向最多 3 次，触顶停、交人。
3. **默认该少，而不是默认该全。** 一次只推进一件可验证的事。S 只许压缩厚度，不许删段。今天该读的更少更准；管子加粗就停。
4. **分层信任。** 高信任（CRUD / UI / 样板）可以自愈；低信任（核心算法 / 安全路径）每轮人判断。不要用自愈掩护不该自动的层。
5. **三重反馈，禁止单点猜。** ① 行为（Playwright）② 前端日志 ③ 后端日志。缺一路，三角定位退化成猜测，烧掉 3 × 3 预算。日志必须实时落盘、可 `tail -f`。
6. **可见即可续。** 有可见面必须能答：看得见的 X → 跨过 &lt;边界&gt; → 仍能做 Y。同进程内存绿不算门闩。
7. **once 不是 keep。** 过程探测给 Agent 看方向；keep 才给人勾 ✅。混报「测过了」= 还没测。
8. **点名才跑，嵌套交还。** 总管与子命令带 `disable-model-invocation`：说了才打开。三条子命令走同一条管道，只是负责的段不同。学习层在管道之上，不是第九段。

## 我们拒绝成为什么

- **又一份复述 README 的散文。** 根文档讲 why。这里只收可执行约定。
- **平行流程。** 不另起第十条管道，不把 SafeClaw 的 `TC-*` / `discover` 假装成本仓能力。
- **无限试错的自愈。** 触顶必须停，把各方向的证据交人。
- **假门闩。** 「从未创建」Fail Fast 冒充 persist、只 mock 流式接口、用 once 截图关账、放宽断言换绿——都是失败。
- **把人拖去点浏览器。** 技能存在的理由就是把这次切换压到零。
- **为技能而技能。** 新夹不进 [Index.md](Index.md)、路由不改 [Agents.md](Agents.md)、身份空转——不许占坑。

## 成功长什么样

人说清意图，说「跑一下」，看截图或报告，说「对」或「这里不对」。手没有离开对话。中间轮次的修复不经过人。

衡量标准不是技能夹有多少、模板有多厚，而是：

- 一件事能从 classify 走到 deliver，进度只认 track，不跳段
- 对不上号时三路信号能交叉定位，而不是猜
- 勾 ✅ 的每一条都是 keep，且因对的原因绿
- 洞关账后能回答：设计当初为何防不住——不是「以后注意」

如果代理仍在每轮把人叫去点菜单、用探测当验收、或把管子加粗包装成降噪——技能层失败了，无论文稿多么完整。

## 气质

冷静、偏宪章，不偏营销。

像一份早晨的出门闩：短、可执行、禁区写死。读者是来办事的，不是来被取悦的。中文是第一语言。
