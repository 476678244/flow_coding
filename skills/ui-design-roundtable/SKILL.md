# UI Design Roundtable

用结构化的设计师圆桌，把「这个页面美不美」推进到「可落地的定版 demo + feature 文档」。

**受 `ljg-roundtable` 启发**（李继刚的「圆桌讨论」剑）：借用它的「一题一桌、定义开场、逐轮交锋、每轮收一张 ASCII 图、用户用指令控节奏」的骨架，但把议题从抽象概念换成**具体页面**，并加两条 UI 专属约束：① 底板必须是真实 DOM；② 大师容易忽视功能，须先钉功能合同。产出物是可实现的设计，而非哲学记录。原始骨架已随本技能存档在 [references/](./references/)，请人前先读。

## 何时用

- 用户想讨论/重构某个页面的美观与体验，且愿意听多种设计理念交锋。
- 已有现网页面（或组件），需要一个能落地的定版，而不是一句「更简洁点」。

## 与 ljg-roundtable 的差异

| 维度 | ljg-roundtable | ui-design-roundtable |
|------|----------------|----------------------|
| 议题 | 抽象概念（自由意志…） | 具体页面 + 真实 DOM 底板 |
| 参会者 | 各领域思想家 | 设计大师（跨「观看距离」互补） |
| 每轮产物 | ASCII 结构图 | ASCII 图 **+** 每人一版 HTML demo |
| 防坑 | — | **先提取功能合同**，禁止删功能求好看 |
| 收场 | 知识网络图 | **分层合稿** + 定版 demo + feature 文档 |
| 存档 | org 笔记 | `docs/ideas/<topic>/` + `docs/features/<id>/` |

## 工作流

复制此清单并逐项推进：

```
- [ ] 1. 定议题 + 锁底板（读真实页面/组件 DOM）
- [ ] 2. 提取功能合同 F1..Fn（从代码，非臆测）
- [ ] 3. 请人：3-5 位真实设计大师，跨观看距离互补
- [ ] 4. 开场定义：各人先答「这个页面美观指什么」
- [ ] 5. 逐轮交锋：每轮收一张 ASCII 图 + 亮指令菜单
- [ ] 6. 每人出一版 refactored HTML（覆盖全部功能合同）
- [ ] 7. 交叉讨论：对着彼此的 HTML 打，不空谈
- [ ] 8. 分层收场：按观看距离把设计分给不同人，出合稿
- [ ] 9. 出定版 demo（绑定真实 data-testid）+ 建 feature 文件夹
```

### 1. 定议题 + 锁底板

议题必须挂在一个真实页面上。用 Read/Grep 把底板的 DOM 摸清：布局容器、`data-testid`、关键组件文件路径。**没有真实底板不开桌**——否则大师会讨论一个不存在的界面。

### 2. 提取功能合同（关键防坑）

**在请人之前**，从代码里列出该页面必须保留的功能 F1..Fn（多轮对话、模型选择、权限可见、版本切换、两级提需求、演示、下载、键盘、空状态、执行可见……），并标注每项的 `data-testid` / 组件文件。

> 铁律：**功能一个不删，只可重排疏密与轻重。** 大师的第一稿几乎都会把功能当装饰砍掉（把对话砍成一行、删版本、删 scope）——这是海报思维。凡出现删功能，立即打回重画。

### 3. 请人

挑 3-5 位**真实**设计大师。**先读 [assets/masters.md](./assets/masters.md)**——已请过的大师花名册（MBTI、立场、独特角度、负责的观看距离、已验证搭配）。标准：

- 覆盖不同「观看距离/维度」：远处印象（如莫奈的光）、上手体验（如 Norman 三层 / 直接操作）、逐像素工艺（如 Jobs/Ive）、信息密度（如 Tufte）、克制（如 Rams）、留白（如原研哉）、构图疏密（如张大千）、减法（如米开朗基罗）。
- 立场要能互相较劲，别都主张「少即是多」。
- 至少一位行外人（平面/绘画/雕塑），专看气质，不负责好不好用。

每人给：姓名、MBTI、一句话立场、为什么请他（他看这个页面的独特角度）。**新请到的大师，回填 [assets/masters.md](./assets/masters.md)。**

### 4. 开场定义

主持人亮底板与名单，抛定义问题：「这个页面『美观』指什么？哪些要素少不了？」每人依次发言。发言格式：

```
【人物名】【行动标签】：内容

简言之：一句话
```

行动标签：`陈述` `质疑` `补充` `反驳` `修正` `综合`。

### 5. 逐轮交锋

每轮三步：**发言**（接着前面的话说，不自说自话）→ **主持人综述**（点破真分歧 + 画一张 ASCII 图：2x2、光谱、因果环、层级树，画结构不复述内容）→ **等指令**：

```
【主持】：(指令: 可 / 止 / 深入此节 / 引入新人物)
```

主持人不站队，每轮只追一个争议点追到底；表面共识要点破。

### 6. 每人出一版 HTML

每位大师按自己的理念重画同一套内容的同一张页，**全部覆盖功能合同 F1..Fn**，只在排布上体现理念差异。写到 `docs/ideas/<topic>/NN-<name>.html`。再写一个 `index.html`（iframe + 顶部切换条）做对照台。遵守用户的主题约束（如「只浅色」）。

### 7. 交叉讨论

主持人要求各人**指着别人的 HTML** 说，不许回到口号。这一步逼出真正的取舍（谁的方案赢了本能层、输了行为层……）。

### 8. 分层收场（出合稿）

不要在九版里投票选一个。**按观看距离分层**，让不同大师各管一层，合成一张：

```
远（整体印象）→ 一人   只进背景，不碰内容
中（上手使用）→ 一人   权限/scope/进度/多轮
近（逐像素）  → 一人   每个零件被决定过
        ▼  内容主角（如幻灯片）三层共同服务
```

写**冲突仲裁规则**（三层打架时谁让谁），例如：内容面积永远归主角；可用性 > 工艺；第一眼归「远」层。

### 9. 出定版 + 建 feature

- 定版 demo 绑定**真实 `data-testid`**，每块标注来源组件文件，让它可直接照改。写到 `docs/features/<feature-id>/demo-<id>.html`。
- 按仓库 [feature 约定](../../../docs/features/README.md) 建文件夹：`README.md`（合同/分层/仲裁/功能触点表/DOM 改动摘要/代码路径）、`problem.md`、`methodology.md`（行为 SoT）、`acceptance.md`（可勾选：三距离 + F1..Fn + 仲裁 + 回归）。
- 在 `docs/features/README.md` 的「现有主题」表登记一行。

## 输出位置

| 产物 | 路径 |
|------|------|
| 圆桌全过程 + 各版 HTML + 对照台 | `docs/ideas/<topic>/`（`roundtable--*.md` + `NN-*.html` + `index.html`） |
| 定版 demo + feature 文档 | `docs/features/<feature-id>/` |

## Fail Fast

- 无真实 DOM 底板 → 不开桌。
- 功能合同未提取 → 不进入请人。
- 任何一版 HTML 缺功能 → 打回重画，不进入交叉讨论。
- 收场若变成「选一个人」而非分层 → 未完成。
